# Operations Runbook

## Storage model (R2 key layout)
- Uploads: `shops/{shop_id}/{kind}/{YYYYMMDD}/{uuid}.{ext}`
- Outputs: `shops/{shop_id}/output/{YYYYMMDD}/{job_id}.{ext}`
- History records: `shops/{shop_id}/history/{YYYYMMDD}/{job_id}.json`
- Heroes collection: `shops/{shop_id}/heroes/...`

## Signed URLs
- Generated by backend with `generate_presigned_url`.
- Typical expiry: 3600 seconds.
- History endpoint refreshes `output_url` each request.

## Incident triage

### A) Login fails
- Verify `backend/shops.json` contains matching `shop_code` + `pin`.
- Check `SHOP_SECRET` consistency across backend restarts (token format depends on it).

### B) Upload fails
- Validate extension is one of jpg/jpeg/png/webp.
- Verify multipart form field name is `file`.
- Confirm R2 credentials + bucket env vars.

### C) Generate fails
- Validate `fabric_key` and `hero_key` exist in R2.
- Confirm `GEMINI_API_KEY` is valid.
- Confirm model name in `GEMINI_IMAGE_MODEL` is available.

### D) Output/history missing images
- Check object exists at `output_key`.
- Ensure signed URL expiry has not elapsed.
- Refresh history to get renewed signed URLs.

### E) Forbidden file access
- `/file` checks key prefix ownership: must start with `shops/{shop_id}/`.

## Observability recommendations
- Add structured logs with correlation id.
- Log endpoint latency + upstream Gemini latency.
- Emit counts for upload/generate success-failure rates.

## Backup/data retention suggestions
- Define retention for history JSON vs output images.
- Apply lifecycle policies per prefix in R2 if cost control needed.
